# P-47II MD タイトル画面差し替え

P-47II MD（The Freedom Star）のタイトル画面を、新ロゴと BG 付きのものに差し替えるパッチです。
元 ROM を直接書き換え、IPS パッチも出力します。

## 変更内容

| 項目 | 内容 |
| --- | --- |
| ロゴ | 「THE FREEDOM STAR」→ `assets/P47_logo_md.png`（MD 用に手直しした 272×56px のドット絵、白縁込み 12 色。無い場合は `assets/P47_logo.png` から縮小・減色・白縁付けで生成）。編隊が飛来して爆発する中から、旧ロゴと同じく爆発の位置に合わせて 1 列ずつ現れる |
| BG | `assets/title_bg.jpg` を 320×224 に切り出し、明るさ 80% で減色（15 色×2 パレット、タイル単位で切り替え＋ディザ）。文字のスライドインと同時に 32 フレームかけてフェードイン |
| 文字 | すべてのタイトル文字に 1px の黒縁（8 方向）を付けた |
| START / OPTION | 1 行下げた（CONTINUE 表示もそれに合わせて 1 行下げた） |
| コピーライト | `©2025 CITY CONNECTION CO.,LTD.`（「.,」は 1 タイルにまとめた字形）。他の行と中心を揃えた |
| カーソル | 黒縁付きの矢印（8×16 スプライト） |

ゲーム本編・オプション画面・デモは元の ROM と同じ画面になることを確認済み（「検証」参照）。

## パッチの当て方

`patch/P-47_II_MD_title.ips` を元 ROM に当てます（Lunar IPS、Flips など）。

| ファイル | サイズ | CRC32 |
| --- | --- | --- |
| 元 ROM `P-47_II_MD_Japan_En.md` | 1,048,576 | `FE9B4C7F` |
| パッチ後 ROM | 1,048,576 | `667D11BC` |

## ビルド

必要なもの: Python 3（Pillow, numpy）、`binutils-m68k-linux-gnu`（`m68k-linux-gnu-as` / `ld` / `objcopy` / `nm`）

```sh
pip install pillow numpy
mkdir -p rom && cp <元ROM> rom/P-47_II_MD_Japan_En.md
python3 tools/patch.py
# -> build/P-47_II_MD_title.md（パッチ後 ROM）, patch/P-47_II_MD_title.ips
```

`tools/patch.py` の処理は次のとおりです。

1. `tools/build_title.py` で画像を減色し、タイル・マップ・パレット・文字列表を `build/title_data.s` に出力する
2. `src/title.s` をアセンブルして ROM の空き領域 `0x085000-`（元は `0xFF` 埋め）に配置する
3. 元のコードにフックを書き込む。フックを書く前に、書き換え位置の元のバイト列が想定どおりか確認する
4. 当て直した IPS がパッチ後 ROM と一致することを確認する

ロゴ・BG を差し替えるときは `assets/` の画像を置き換えて再ビルドします。
`P47_logo_md.png` は減色せずそのまま使うため、色はメガドラの段階値（0, 34, 68, …, 238）、透明を除いて 15 色以内にしてください。
レイアウトや明るさは `tools/build_title.py` 冒頭の定数で調整できます。

## 仕組み

### VRAM・パレットの割り当て（タイトル画面の間だけ）

| 資源 | 用途 |
| --- | --- |
| PAL0 / PAL2 | BG。初期は黒で、文字スライド中に目標色×k/32 を毎フレーム書き込む |
| PAL1 | 新ロゴ（ROM `0x017096` の初期パレットを書き換え） |
| PAL3 | 文字・スプライト（既存のまま。文字は色 15=白、色 1=黒） |
| Plane A | ロゴ（行 5-12、列 2-37）と文字。文字は列 40 以降に描き、ライン H スクロールでスライドさせる |
| Plane B | BG（行 0-27） |
| タイル | 1253 枚（ロゴ 169、文字 76、カーソル 2、BG 1006）。タイトル専用の空き領域に置く: `0x2000-0x5FFF`、`0x7200-0x7FFF`、`0x8000-0xAFFF`、`0xB000-0xB3FF`（ウインドウ面、未使用）、`0xBA80-0xBFFF`、各プレーンの 28 行目以降。既存のスプライト（`0x0000-`）とフォント（`0x6000-`）には触れない |

### 元コードへのフック

| アドレス | 元の処理 | 変更 |
| --- | --- | --- |
| `0x001C82` | 各画面の初期化の共通処理（画面オフ・消去） | `TitleExitClear`: タイトルの後なら（VRAM `0xFFFC` の目印で判定）、タイトル用に借りた `0xB000-0xB3FF`・`0xBA80-0xBFFF`・`0xCE00-0xDFFF`・`0xEE00-0xFFFF` を 0 に戻す |
| `0x0167C0` | タイトル初期化のプレーン消去 | `TitleInit`: 続けて新タイルと BG マップを VRAM に書き込む（画面オフ中） |
| `0x017096` | ロゴのパレット | 新ロゴのパレット |
| `0x016B3A` | 旧ロゴを 1 列ずつ描く | `TitleReveal`: 新ロゴ 36 列を同じ速さ・同じ位置関係で描く |
| `0x016C6A` | スキップ時の旧ロゴ一括描画 | `TitleFullLogo` |
| `0x07F800` | 文字列表（1 行目・START・OPTION・コピーライト） | 黒縁付きの文字列表（コピーライトはスライド開始時に描く） |
| `0x016C10` | CONTINUE と残り回数 | `TitleCont`: 黒縁付き、1 行下げる。数字 0-9 を用意 |
| `0x016D38` | スキップ時のフェード | `TitleSkip`: コピーライトを描き、BG を含む全パレットへフェード |
| `0x016D56` / `0x016D86` | 文字スライドとライン H スクロール | `TitleSlide` / `TitleBands`: BG の明るさ更新、スクロール帯を 111-159 / 160-223 に変更 |
| `0x016E10` 他 | カーソル（8×8） | 8×16 の黒縁矢印 |
| `0x016EDE` 他 | 隠しメニュー（左+C） | 通常メニューの黒縁タイルを消してから元の文字を描く |

### 補足

- コピーライトは 29 文字あり、H スクロールで隠せる幅（192px）より広いため、スライド開始時に描いています。1 コマ目は 1 コマ先の位置から始めるので、末尾が画面左端へ回り込んで見えることはありません。
- デモ・ゲームはプレーンを 128×32 に切り替えるため、タイトルで借りた `0xCE00-` / `0xEE00-` がマップとして、`0xB000-` がウインドウ（HUD）として使われます。これらを 0 に戻さないと、ステージのマップが書き込まれるまでの間にタイルデータがゴミとして映ることがあるので、タイトルを抜けた後の最初の画面初期化で消しています。
- タイトル開始時の VRAM 転送（約 3 フレーム）と、抜けた後のクリア（約 1 フレーム）のため、以降の画面は元より少し遅れて始まります（ゲーム開始は 1 フレーム、デモは 4 フレーム。内容は同一）。
- CONTINUE の横位置は元の ROM と同じく START より 1 文字左です。
- ヘッダのチェックサムは元の ROM と同じく `0000` のままです。

## 検証

`tools/mame/` に MAME（`megadrij`）の Lua スクリプトがあり、ボタン操作、RAM 書き換え、スクリーンショット、VRAM ダンプを台本で実行できます。

```sh
tools/mame/run.sh build/P-47_II_MD_title.md work/snap "400:press:P1_Start;700:shot;701:exit"
```

確認した項目:

- 通常のタイトル演出（ロゴ出現、文字スライド＋BG フェードイン、完成画面）。完成画面は `build/preview_final.png` とカーソル以外で一致
- 演出中にスタートでスキップ
- コンティニュー表示（残り 3・5・9）とカーソル移動
- 隠しメニュー
- ゲーム開始後の画面が元の ROM と完全一致
- オプション画面の出入りが元の ROM と完全一致
- 放置デモが元の ROM と同一（3 フレーム遅れ）
- Mednafen でもストーリーデモ→タイトルの流れで表示を確認

その他のツール: `tools/vdp.py`（VRAM ダンプから画面を再現）、`tools/m68dis.py`（逆アセンブル）、`tools/mame/trace_vram.lua`（VDP 書き込みの記録）、`tools/mame/bp.lua`（ブレークポイント）

## BLACK LABEL（裏モード・試作中）

Rank 3（BLACK）として実装中。Easy / Normal / Hard の動作は元の ROM と同じ。
試作版では、タイトルで **C を押しながら START** を選ぶと BLACK LABEL で始まる（タイトルに戻ると元の Rank に戻る）。
クリア後の解放・SRAM 保存・タイトル表示は未実装。

**確認用の無敵**: タイトルで **左+C** を押すと隠しメニューが出る（元の ROM にある機能）。

1. カーソルを `NO DEATH` に合わせてボタンを押し、`ON` にする（自機が敵弾や敵に当たってもミスにならない）。
2. `START` で始める。**C を押しながら START** なら BLACK LABEL で始まる（隠しメニューの START に `0x016EFC` でフックを追加）。

| 項目 | BLACK の内容 | 実装（`src/black.s`） |
| --- | --- | --- |
| 敵弾 | 速さは元のまま（弾が増えた分の処理落ちで実質遅くなるため）。±12 度・±24 度の弾を追加して 5-way（プールの空きが少ないときは減らす） | 敵弾生成 `0x0117A6` |
| 敵弾の上限 | 32 発（元は面ごとに 18〜26 発。使用中ビットが 32 ビットのため上限 32） | プールを RAM `0xFFB400` へ移設、ステージ／ボス開始時に 32 発に |
| スプライト | 敵弾用の表（32 枠）と元の表から表示中の枠だけを詰めて 80 枠に収め、VDP へ送る。敵弾の並び順を毎フレームずらし、横 1 ライン 20 枚を超えたときは消えずに点滅させる | フレームの最後 `0x001128`、DMA 転送元 `0x0013C8` |
| 追加編隊 | 飛行ザコ（耐久力 6 以下で縦にも動く 21 種類）が出たら 40 フレーム後に同じ編隊をもう 1 組。パレット 2 の部分をパレット 3 で描き、黄色（色 8・12）を深緑（色 7）に置き換えた色違い。置き換えたタイルは表示時に VRAM の空き（`0xBA80-0xBFFF`、`0xB180-0xB3FF`）へコピーして使う（面ごとに 14〜42 枚） | 出現リスト `0x023090`、敵の絵 `0x010540` |
| ザコの耐久力 | 1.5 倍 | 出現時 `0x010390` |
| ボスの耐久力 | Hard の 1.5 倍 | `0x011E46`（Rank 別の 3 値の表） |
| 自機の当たり判定 | 横 15→5 ドット（縦 3 ドット、中心は同じ） | 当たり判定の表 `0x001FD0` |
| ザコの速さ | 飛行ザコだけ 4 フレームに 1 回もう 1 歩（約 1.25 倍、軌道は同じ）。地上物は BG と一緒に動くため速くしない | 移動 `0x0105B8` |

BLACK 用 RAM（全ステージで未使用を確認）: `0xFF3300-`（敵弾の表・送信用の表・作業用）、`0xFFB400-0xFFBBFF`（敵弾プール）。全 6 面をボス戦・面クリアまで遊んで、一度も 0 以外にならない領域を選んだ（`0xFFA326-0xFFAE65` はボス戦で使われる）。
敵弾プールの移設は全ランク共通（Easy／Normal／Hard の画面は元の ROM と同じ）。

調整用: `tools/bl_stats.py`（ダンプから敵弾数・プール満杯率・ライン毎のスプライト数を集計）、`tools/mame/wp.lua`（ウォッチポイント）。
